Where the content comes from, and what it needs that doesn’t exist

  • The ten dated posts are Earl of East’s approved October list (build-d-approval-phase2.md §1). Frame A shows them pre-approval, frame B post-approval — same dates, because approval writes no structural change (0/10 drift).
  • The draft dot on the month control has no field behind it. loadCycleList already calls cyclesWithReviewableDraft() — it uses exactly this fact to decide whether a draft-only cycle qualifies for the menu — but CycleSummary does not carry it to the client. Spec gap 2. Round 2 makes it more load-bearing: with the pills gone, the month control is the only place a draft month announces itself before you arrive on it.
  • Dot density for a month you have not opened still needs a read that does not exist. GET /api/plan serves the viewed cycle’s posts; GET /api/plan/draft serves one cycle’s planned posts. Spec gap 3. With arrows as the only month mechanism the honest fallback is to paint dots on arrival — the arrow already triggers a switchCycle fetch, so there is no empty-grid flash to design around.
