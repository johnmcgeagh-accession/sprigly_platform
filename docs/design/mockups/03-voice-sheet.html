Implementation notes

  • The waveform is a Web Audio AnalyserNode: getByteFrequencyData into ~25 bars on requestAnimationFrame, amplitude driving bar height. Mocked here as a CSS animation showing both states; the real one is driven by the mic stream, and it flatlines when RMS falls under a floor rather than when the stream stops.
  • Reduced motion is honoured — the bars hold a static mid height rather than animating (see the prefers-reduced-motion block in the stylesheet).
  • Capture: useSpeechInput.ts drives the Web Speech API browser-side, appends final transcript chunks into an editable field, and degrades properly (unsupported hides the mic, no-permission reports itself). IntakeCapture.tsx already uses it.
  • Submit: both modes post to POST /api/plan/draft/apply {op:'text', text}. That route takes no source field, so spoken and typed input are indistinguishable on the ledger — spec gap 8, and it should land with this sheet.
  • The example prompts are written, not recorded. No client-facing prompt copy exists in the repo. They are phrased to elicit intents the classifier can actually route — launch, event, emphasis — rather than open questions the contract cannot express.
