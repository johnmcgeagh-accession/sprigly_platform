Desktop plan surface — the state set

Nine files, fifteen frames, all at real pixels: 1440 × 900 (the [desktop] e2e project’s own viewport) plus two at 1024 × 820. Open any file directly — no build step, no server, no JavaScript.

The spec these illustrate is docs/design/desktop-plan-surface.md; the mobile surface they translate is mobile-plan-surface.md and its own mockup set. Every colour reads a --t-* token, every type size is one of DESIGN.md’s ten roles, and every figure on every screen is a reported one.

What this set is, and is not

  • It is a translation. Every hard decision was already made and reviewed across six rounds on the phone: the vocabulary, the tokens, the mint ramp, the native type stack, the grounded beats and their evidence, the month summary and its CTA, the draft/committed distinction. This set carries all of it and changes the information architecture only where the form factor forces it.
  • Two exceptions, both deliberate. The conversation is docked and persistent rather than summoned, and month and day sit side by side rather than being switched views. The spec argues both and states what each costs.
  • It is a rendering brief. No data model, no generation path, no cycle rule and no agent behaviour changes. The one thing on any screen here that no API serves is the pair of ringed cells in mockup 5, and it needs none — it is a client-side read of the open turn’s own resolved dates.
  • Nothing is invented. Every metric, date, title, caption and count is a reported one, and the six places where a figure could not be sourced are labelled on the page that shows them rather than filled in.
