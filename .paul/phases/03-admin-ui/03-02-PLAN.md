<objective>
## Goal
Routing rule builder UI — list, detail, create, toggle enabled, delete — in the Sprigly admin.

## Purpose
Routing rules are the core config that connects sources to workflows to destinations. Operators need to view what rules exist, create new ones, and enable/disable them without touching the DB directly.

## Output
Four files: list page, detail page, create page, server actions. All data operations via Drizzle Server Components + Server Actions.
</objective>

  <action>
    **List page** (`/admin/routing-rules/page.tsx`):
    - Server Component, queries routingRules joined to clients on clientId
    - Table columns: Client name, Source (monospace badge), Workflow ID, Conditions count (`matchConditions.length`), Priority, Enabled (green/grey badge)
    - Each row has "View →" link to `/admin/routing-rules/{id}`
    - "New rule" link button (top right) → `/admin/routing-rules/new`
    - Empty state: "No routing rules yet."
    - Import: `db, routingRules, clients` from `@sprigly/db`; `eq, desc` from `drizzle-orm`
    - Join: `.innerJoin(clients, eq(routingRules.clientId, clients.id))`
    - Order by: `desc(routingRules.priority)`

    **Detail page** (`/admin/routing-rules/[id]/page.tsx`):
    - Server Component; params.id is the rule UUID
    - Query: full rule row + client name (innerJoin)
    - `notFound()` if no row returned
    - Sections:
      1. Header: client name, source badge, workflowId, priority, enabled badge, edit/action buttons
      2. Match Conditions: table with columns `field | op | value | case-sensitive` — iterate `rule.matchConditions as Array<{field:string, op:string, value:string, caseSensitive?:boolean}>`
      3. Destinations: list — iterate `rule.destinations as Array<{destinationId:string, requireApproval?:boolean, settings?:Record<string,unknown>}>`, show destinationId + JSON.stringify(settings) in a code block
      4. Actions: two `<form>` elements using Server Actions (imported from `./actions`)
         - Toggle form: hidden inputs `id` + `enabled` (inverted), submit label "Disable" or "Enable"
         - Delete form: hidden input `id`, submit button "Delete", add `data-confirm` attribute (or just a plain button — no JS confirm needed for v0.1)
    - Type assertion pattern: `(rule.matchConditions as Array<{field:string,op:string,value:string,caseSensitive?:boolean}>)`
    - `clientConfigId` shown as UUID or "—" if null
  </action>

    Pages render without runtime errors when visited.
  </verify>

<task type="auto">

  <files>
    engine/apps/web/src/app/admin/routing-rules/actions.ts,

  <action>
    **`actions.ts`** — top-level `'use server'` directive:

    ```
    createRoutingRule(formData: FormData): Promise<void>
    ```
    - Read fields: clientId, source, workflowId, matchConditionsJson, destinationsJson, priority, enabled
    - Parse JSON strings: `JSON.parse(matchConditionsJson)` and `JSON.parse(destinationsJson)` — wrap in try/catch, throw on invalid JSON
    - `await db.insert(routingRules).values({ clientId, source, workflowId, matchConditions: parsed, destinations: parsedDest, priority: Number(priority), enabled: enabled === 'on', clientConfigId: null })`
    - `revalidatePath('/admin/routing-rules')`
    - `redirect('/admin/routing-rules')`
    - Imports: `db, routingRules` from `@sprigly/db`; `revalidatePath` from `next/cache`; `redirect` from `next/navigation`

    ```
    toggleEnabled(formData: FormData): Promise<void>
    ```
    - Read: id, enabled (string 'true'/'false')
    - `await db.update(routingRules).set({ enabled: enabled === 'true' }).where(eq(routingRules.id, id))`
    - `revalidatePath('/admin/routing-rules')`
    - `revalidatePath(\`/admin/routing-rules/\${id}\`)`

    ```
    deleteRoutingRule(formData: FormData): Promise<void>
    ```
    - Read: id
    - `await db.delete(routingRules).where(eq(routingRules.id, id))`
    - `revalidatePath('/admin/routing-rules')`
    - `redirect('/admin/routing-rules')`

    Imports for actions.ts: `db, routingRules` from `@sprigly/db`; `eq` from `drizzle-orm`; `revalidatePath` from `next/cache`; `redirect` from `next/navigation`

    ---

    **Create form** (`/admin/routing-rules/new/page.tsx`):
    - Server Component; queries `clients` to populate the clientId select
    - `<form action={createRoutingRule}>` (import from `../actions`)
    - Fields:
      - `clientId`: `<select>` with options from DB (value=id, label=name)
      - `source`: `<select>` with options: `email`, `webhook`
      - `workflowId`: `<input type="text">` — placeholder `sprigly-blog-post`
      - `matchConditionsJson`: `<textarea>` — default value:
        ```json
        [{"field":"subject","op":"startsWith","value":"Blog:","caseSensitive":false}]
        ```
      - `destinationsJson`: `<textarea>` — default value:
        ```json
        [{"destinationId":"db-save-blog-post","requireApproval":false,"settings":{}}]
        ```
      - `priority`: `<input type="number">` default `10`
      - `enabled`: `<input type="checkbox">` default checked
    - Submit button: "Create rule"
    - Back link: `← Routing Rules` → `/admin/routing-rules`
    - Styling: consistent with other admin pages (white card, border, labels above inputs)

    **Note on textarea defaultValue in Server Components:**
    Use `defaultValue` prop on `<textarea>` (not `value`) — Server Components render HTML directly so `defaultValue` becomes the initial content correctly.
