<objective>
## Goal
Implement `@sprigly/destinations` with two destinations (`db-save-blog-post` and `gmail-send-notification`), then extend the DB seed script with Sprigly's `clientConfig`, routing rule, and blog-post prompt templates. After this plan, a `Blog:` email can be routed end-to-end from GmailPoller through WorkflowRunner to destinations that save the post and send a notification.

## Purpose
Destinations are the delivery end of the engine — the part that turns workflow output into observable results. The two destinations here cover the core v0.1 loop: blog post saved to DB (ready for admin review) and notification email sent back to John (so he knows it's ready). The seed data wires Sprigly's own routing rule and prompt templates so the worker (02-05) can run the full pipeline without manual DB setup.

    **engine/packages/destinations/src/notification/compose-email.ts:**

    Pure function — no imports from DB or googleapis.

    ```typescript
    export interface EmailParams {
      toEmail: string;
      fromEmail: string;
      title: string;
      excerpt: string;
      targetKeyword: string;
      authorName: string;
    }

    export function composeNotificationEmail(params: EmailParams): string {
      const { toEmail, fromEmail, title, excerpt, targetKeyword, authorName } = params;
      const body = [
        `Hi ${authorName},`,
        '',
        `Your blog post has been drafted and saved for review.`,
        '',
        `Title: ${title}`,
        `Keyword: ${targetKeyword}`,
        '',
        `Excerpt:`,
        excerpt,
        '',
        `Log in to /admin/blog to review and publish.`,
        '',
        `Sprigly`,
      ].join('\r\n');

      return [
        `To: ${toEmail}`,
        `From: ${fromEmail}`,
        `Subject: Blog post ready: ${title}`,
        `Content-Type: text/plain; charset=utf-8`,
        `MIME-Version: 1.0`,
        '',
        body,
      ].join('\r\n');
    }
    ```

    - `requiresApproval(config: DestinationConfig): boolean` — always `false` (notifications are fire-and-forget)
    - `async deliver(output: unknown, event: IncomingEvent, config: DestinationConfig): Promise<DeliveryResult>`:
      1. Cast: `const post = output as BlogPostOutput`
      2. `const toEmail = config.settings['toEmail'] as string | undefined` — if undefined: return `{ success: false, error: 'toEmail not configured' }`
      3. `const tokens = await getTokens(this.db, this.encProvider, event.clientId, 'gmail')` — if null: return `{ success: false, error: 'No Gmail tokens for client' }`
      4. Build OAuth2 client:
         ```typescript
         const auth = new google.auth.OAuth2(this.googleClientId, this.googleClientSecret);
         auth.setCredentials({
           access_token: tokens.accessToken,
           ...(tokens.refreshToken !== undefined && { refresh_token: tokens.refreshToken }),
           ...(tokens.expiresAt !== undefined && { expiry_date: tokens.expiresAt }),
         });
         auth.on('tokens', (newTokens) => {
           // persist refreshed tokens (same pattern as GmailApiClient)
           const refreshed = { ... }; // same spread-conditional pattern as gmail-client.ts
           void storeTokens(this.db, this.encProvider, event.clientId, 'gmail', refreshed);
         });
         ```
      5. `const gmail = google.gmail({ version: 'v1', auth })`
      6. Get sender email: `const fromEmail = tokens.emailAddress ?? toEmail`
      7. Compose message:
         ```typescript
         const raw = composeNotificationEmail({
           toEmail,
           fromEmail,
           title: post.title,
           excerpt: post.excerpt,
           targetKeyword: post.targetKeyword,
           authorName: post.author,
         });
         const encodedMessage = Buffer.from(raw).toString('base64url');
         ```
      8. Send: `await gmail.users.messages.send({ userId: 'me', requestBody: { raw: encodedMessage } })`
      9. Return `{ success: true, metadata: { toEmail } }`
      10. Wrap in try/catch: return `{ success: false, error: String(err) }` on failure

    For the token refresh in the `tokens` event, use the same `typeof newTokens.refresh_token === 'string'` guard as `gmail-client.ts` (avoids null assignment issue).
