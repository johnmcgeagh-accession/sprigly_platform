# Destinations

## Purpose

`@sprigly/destinations` contains the delivery layer: classes that know how to send workflow output somewhere. Each destination receives the workflow's output, the original event, and a `DestinationConfig` (from the routing rule or the workflow's defaults), and delivers accordingly.

`DestinationDispatcher` in `packages/engine/src/destination-dispatcher.ts` orchestrates delivery. It holds a registry of destination instances, resolves which configs apply, handles the approval gate, and calls each destination's `deliver()` method. Workflows do not interact with destinations directly -- they return output and the consumer calls the dispatcher.

---

## Interface

### `Destination`

Defined in `packages/engine/src/types.ts`:

```typescript
interface Destination<TOutput = unknown> {
  id: string;
  deliver(
    output: TOutput,
    event: IncomingEvent,
    config: DestinationConfig,
    ctx: DeliveryContext,
  ): Promise<DeliveryResult>;
  requiresApproval(config: DestinationConfig): boolean;
}
```

`requiresApproval()` is called before `deliver()`. If it returns `true`, the dispatcher inserts a row into `approvals` and skips `deliver()` for that run. The output snapshot is stored in `approvals.output_snapshot`.

### `DestinationDispatcher`

`packages/engine/src/destination-dispatcher.ts`.

```typescript
class DestinationDispatcher {
  register(destination: Destination): void
  async dispatch(
    output: unknown,
    event: IncomingEvent,
    rule: RoutingRule,
    runId: string,
    defaultDestinations?: DestinationConfig[],
  ): Promise<void>
}
```

**Destination config resolution order:**
1. If `rule.destinations.length > 0`: use the rule's destinations.
2. Otherwise: use `defaultDestinations` (from the workflow's `defaultDestinations` array).
3. If both are empty: log a warning, deliver nothing.

### `DestinationConfig`

```typescript
interface DestinationConfig {
  destinationId: string;
  requireApproval?: boolean;
  settings: Record<string, unknown>;
}
```

The `settings` shape is destination-specific. See per-destination sections below.

### `substituteTemplate(template, vars)`

`packages/destinations/src/generic/template.ts`. Replaces `{{key}}` and `{{nested.key}}` placeholders in a template string with values from a vars object. Supports dot-path notation for nested access:

```typescript
substituteTemplate('{{brandName}} brief', { brandName: 'Acme' })
// → 'Acme brief'

substituteTemplate('{{data.title}}', { data: { title: 'Hello' } })
// → 'Hello'
```

Returns empty string for paths that resolve to `null`, `undefined`, or a missing key.

## Registered destinations

### `db-save-output`

`packages/destinations/src/generic/db-save-output.ts`. Saves workflow output to `workflow_outputs` as a `draft` row. Always available. `requiresApproval()` always returns `false`.

**Output handling:** If the output object has a top-level `data` field that is an object, only `data` is stored. This strips the `pdf` Buffer and envelope fields (e.g. `brandName`, `summaryBullet*`) from prospect research output before writing to JSONB. If there is no `data` field, the full output is stored (with Buffers replaced by `'[binary]'` via `stripBuffers()`).

**`settings`:** No settings. Pass `{}`.

---

### `db-save-blog-post`

`packages/destinations/src/blog-post/db-save-blog-post.ts`. Writes a `BlogPostOutput` to the `blog_posts` table. Generates `previewToken` and `publishToken` UUIDs. Handles slug uniqueness by appending `-2`, `-3`, etc. up to 100 attempts before throwing.

**`requiresApproval()`:** Returns `config.requireApproval === true`. The default routing rule in `seed.ts` sets `requireApproval: false`.

**`settings`:** No settings. Pass `{}`.

---

### `gmail-send-notification`

`packages/destinations/src/notification/gmail-send-notification.ts`. Sends a plain-text email from the client's Gmail account. Uses the client's Gmail OAuth tokens to authenticate. `requiresApproval()` always returns `false`.

**Recipient resolution:**

| `settings.to` value | Resolves to |
|---|---|
| `"sender"` | `event.reply.data['from']` -- the From address of the triggering email |
| Any other string | Used as a literal email address |

**Subject:** `settings.subject` if set, otherwise `"Output ready: <title>"` where `title` is read from the output object if it has a string `title` field.

**Body:** Generated by `formatOutputAsText()` in `packages/destinations/src/notification/compose-email.ts`.

**`settings` shape:**
```typescript
{
  to: 'sender' | string;  // required
  subject?: string;       // optional; auto-generated if absent
}
```

---

### `gmail-reply-with-attachment`

`packages/destinations/src/generic/gmail-reply-with-attachment.ts`. Sends an email with an attachment directly (not as a draft) from the client's Gmail account. Expects the workflow output to contain a `pdf` field that is a `Buffer`. `requiresApproval()` returns `config.requireApproval === true`.

**Recipient resolution:**

| `settings.to.mode` | Resolves to |
|---|---|
| `'sender'` | `event.reply.data['from']` |
| `'address'` | `settings.to.address` |

**Template substitution:** `subjectTemplate`, `bodyTemplate`, and `attachmentFilenameTemplate` are processed with `substituteTemplate()` against the full output object. Any field in the output can be referenced with `{{fieldName}}`.

**Attachment filename sanitisation:** Non-alphanumeric characters (except `.`, `_`, `-`) are replaced with `-` to produce a safe filename.

**`settings` shape (`GmailReplyWithAttachmentSettings`):**
```typescript
{
  to: { mode: 'sender' } | { mode: 'address'; address: string };
  subjectTemplate: string;            // e.g. 'Prospect brief: {{brandName}}'
  bodyTemplate: string;               // e.g. 'PDF attached.\n...'
  attachmentFilenameTemplate: string; // e.g. '{{brandName}}-prospect-brief.pdf'
  attachmentMimeType?: string;        // defaults to 'application/pdf'
  bodyMimeType?: 'text/html' | 'text/plain';  // defaults to 'text/plain'
}
```

**MIME construction:** `composeMimeWithAttachment()` in the same file builds a `multipart/mixed` MIME message manually (not via a library). The raw MIME string is base64url-encoded and sent via `gmail.users.messages.send`. This function is currently inline in the file and should be extracted to a shared utility if a second attachment-sending destination is added (see BACKLOG).

## How to extend

### Adding a new destination

1. Create `packages/destinations/src/<name>/<destination-name>.ts` implementing the `Destination` interface.
2. Export the class from `packages/destinations/src/index.ts`.
3. Register an instance in `apps/worker/src/index.ts`:
   ```typescript
   dispatcher.register(new YourDestination(db, ...));
   ```
4. Add the destination's `settings` shape to this doc.
5. To use the destination from a routing rule, set `destinationId` to the class's `id` string in the routing rule's `destinations` JSONB.

The destination's `id` string is what routing rules and workflow `defaultDestinations` reference. It must be globally unique across registered destinations.

## Gotchas

**`db-save-output` unwraps `output.data`.** If your workflow output has a top-level `data` field, only `data` is written to `workflow_outputs.output`. Fields at the root level alongside `data` (like `pdf`, `brandName`, `summaryBullet*`) are silently dropped. This is intentional for prospect research -- the PDF bytes should not be stored in JSONB. If your workflow's root-level fields need to be preserved, do not name the typed result field `data`, or use a different destination.

**`gmail-send-notification` and `gmail-reply-with-attachment` have duplicated OAuth token refresh logic.** Both classes construct a Google OAuth2 client and wire up an `auth.on('tokens')` callback to refresh and re-persist tokens. This is boilerplate that should eventually be extracted to a shared helper. If a bug is found in the token refresh flow, check both files.

**Template substitution uses dot paths; `fillTemplate` in workflows uses `{{key}}` only.** `substituteTemplate()` in `destinations/src/generic/template.ts` supports `{{nested.key}}` dot paths. The `fillTemplate()` functions inside individual workflows (blog post, prospect research) match `{{key}}` only. They are separate implementations. See BACKLOG for the planned consolidation into a shared utility.

**Attachment send is not a reply-in-thread.** `GmailReplyWithAttachment.deliver()` calls `gmail.users.messages.send()` directly -- it does not set `threadId` or `In-Reply-To` headers to thread the reply with the original message. The result is a new email from the client's Gmail, not a reply in the same thread. `GmailApiClient.createDraft()` supports `threadId` but that path is not currently used by `GmailReplyWithAttachment`.

**Delivery failures do not fail the job.** `DestinationDispatcher.dispatch()` catches errors from individual `destination.deliver()` calls and logs them, but continues to the next destination. A failed delivery does not mark the workflow run as failed. Check the worker pino logs for `[engine] DestinationDispatcher: delivery failed` lines.
