# Lean-Line Pipeline — Monthly Content Request

## 1. Overview

Once a month, for each active client channel, the pipeline drafts a content-request email to the client. The email opens with a one-to-two-sentence "lean-line" — a data-driven recommendation generated by comparing last month's top-selling products against last month's best-performing Instagram posts. Wherever a product sold strongly but never appeared in a high-engagement post, that gap is surfaced as an opportunity; wherever a product both sold well and posted well, the overlap is noted. After the lean-line comes a fixed question set (plus any per-client extras) that invites the client to share their direction for the coming month. The output is a Gmail **draft** only — a human reviews and sends it. Nothing is transmitted automatically.

## 2. Components

### ig-producer — `src/ig-producer.ts` / `src/ig-trawl.ts`

Trawls last month's Instagram posts for a given handle via the Apify `apify~instagram-scraper` actor (`run-sync-get-dataset-items` endpoint). Key behaviour:

- Fetches up to `APIFY_RESULTS_LIMIT = 50` posts with a 120-second abort timeout.
- Filters to posts where `ownerUsername` matches the configured `instagram_handle` (case-insensitive). Tagged/mention posts from other accounts are dropped with an info log; this is normal actor behaviour.
- Throws only if zero owned posts are returned — that indicates a handle mismatch or account transfer.
- Skips posts where `likesCount` or `commentsCount` is negative or null (hidden counts); logs at info, does not fail.
- Filters the owned set to posts whose timestamp falls within the data month in Europe/London time.
- Validates the mapped array against `igPostSchema` (the shared Zod contract; see §3).
- Writes `instagram-posts-YYYY-MM.json` to the client's Drive folder using `updateFile` if the file exists, `createFile` if not (idempotent).

`ig-trawl.ts` is the CLI entry point. It resolves the client and channel from slug + channel name, reads `APIFY_API_KEY` from env, and delegates to `trawlInstagramPosts`.

### lean-line reader — `src/lean-line.ts`

Reads the two Drive data files, ranks them, calls the Haiku model, and returns a plain-English lean-line string, or `null` when both sources are absent.

**Four degradation branches:**

| Sales CSV | IG JSON | Behaviour |
|---|---|---|
| Present | Present | Both-sources path. Bias toward products that appear in both top-sellers and top-posts. Flag top sellers with no matching post as under-posted. |
| Present | Absent | Sales-only path. One short clause acknowledging missing engagement data; lean-line still generated. |
| Absent | Present | Engagement-only path. One short clause acknowledging missing sales data; lean-line still generated. |
| Absent | Absent | Returns `null`. Caller omits the lean section entirely — no placeholder, no empty line. |

The caller (`runRequestEmail`) **must** check for null and omit the lean section; it must never render a blank intro.

### request-email worker — `src/content-cycles/request-email.ts` / `src/content-cycles/stubs.ts`

Assembles and drafts the monthly content-request email. Entry point is `requestEmailStub` in `stubs.ts`, which self-bootstraps dependencies (Drive tokens, model client, Gmail draft service) and delegates to `runRequestEmail`.

`runRequestEmail` flow:

1. Look up the content cycle by `(clientId, channel, cycleMonth)`. If `status === 'requested'`, return early — idempotent on double-enqueue or retry.
2. Resolve `clientName` from `clients.name` (DB).
3. Resolve `driveFolderId` from `clientChannels` (DB).
4. Download `calendar-config.json` from the Drive folder. Extract `contact_email` (required — throws if absent), `contact_name` (optional, falls back to `contact` if it is a plain name rather than an email address, then to "Hi there,"), and `extra_questions` (optional string array).
5. Call `buildLeanLine` using `dataMonth` for data lookups.
6. Compute `targetMonth = dataMonth + 1 calendar month`. Build the subject and month label from `targetMonth`.
7. Assemble body: greeting → intro → lean-line (if non-null) → transition → numbered questions (base 5 + per-client extras) → sign-off.
8. Call `gmailDraftService.createDraft` — **never** send. If it returns `null`, throw and leave the cycle in `scheduled` so it retries.
9. On confirmed draft creation, transition the cycle `scheduled → requested` via `transitionCycle`.

## 3. Data Contracts

### `sales-YYYY-MM.csv`

Shopify "Total sales by product" export. Required columns (matched by header name, not position):

- Product: matched against `product title`, `product name`, `product`, `title`, `item`
- Quantity: matched against `net items sold`, `items sold`, `net quantity`, `units sold`, `quantity sold`, `qty sold`, `quantity`
- Date (optional): matched against `day`, `date`, `order date` — used to filter to the target month

If a date column is absent, all rows are treated as belonging to the month. If the product or quantity column is unrecognised, the file returns zero sellers and the pipeline degrades to engagement-only.

**Source:** manual Shopify export by the client or operator, uploaded to the client's Drive folder via `pnpm drive-upload`. No automated producer exists yet.

---

### `instagram-posts-YYYY-MM.json`

Produced by `ig-trawl`. Validated against `igPostSchema` (exported from `lean-line.ts`) at both the producer (write) and reader (parse) ends:

```typescript
z.object({
  timestamp:     z.string(),
  caption:       z.string().optional(),
  likesCount:    z.number().int().nonnegative(),
  commentsCount: z.number().int().nonnegative(),
})
```

Both ends must be kept in sync with this schema. If the Apify actor changes its output shape, update `igPostSchema` and both validation call sites.

---

### `calendar-config.json` — fields consumed by this pipeline

| Field | Required | Purpose |
|---|---|---|
| `instagram_handle` | Yes (for ig-trawl) | Account guard — filters out tagged/mention posts from other accounts |
| `contact_email` | Yes (for request-email) | Draft recipient address |
| `contact_name` | No | Greeting name ("Hi Sally,"). Falls back to `contact` if it is not an email address, then to "Hi there," |
| `extra_questions` | No | String array appended after the base five questions, numbered continuously |

## 4. The Month Model

The pipeline uses two distinct month values:

- **`dataMonth`** = `cycleMonth` (e.g. `2026-05`) — the calendar month whose data is analysed. `buildLeanLine` reads `sales-2026-05.csv` and `instagram-posts-2026-05.json`.
- **`targetMonth`** = `dataMonth + 1 calendar month` (e.g. `2026-06`) — the month the email is planning for. All client-facing text uses `targetMonth`: the subject line ("content plan for June 2026"), the question framing ("next month's content").

December rolls over correctly: `dataMonth = 2026-12` → `targetMonth = 2027-01` → label "January 2027".

**Do not confuse them.** The lean-line is written about May's data but points toward June's plan.

## 5. Running It Manually

Run these commands in order from `engine/apps/worker`.

**Step 1 — Refresh the IG posts file for the data month:**

```bash
pnpm ig-trawl <slug> instagram <YYYY-MM>
# e.g.
pnpm ig-trawl ivy-t instagram 2026-05
```

This calls Apify (up to 120s), filters and validates, and writes `instagram-posts-2026-05.json` to the client's Drive folder. Idempotent — safe to re-run.

**Step 2 — Trigger the request-email worker:**

```bash
pnpm send-request-email <slug> <channel> <YYYY-MM>
# e.g.
pnpm send-request-email ivy-t instagram 2026-05
```

This seeds a `scheduled` cycle if one does not exist, then runs `requestEmailStub`. The worker reads the Drive data, generates the lean-line, assembles the email body, creates the Gmail draft, and transitions the cycle to `requested`.

**Step 3 — Review and send the draft:**

Open Gmail at the `contact_email` address (currently `john.mcgeagh@gmail.com` for testing). The draft subject is `<ClientName> — content plan for <Month YYYY>`. Review, adjust if needed, then send manually.

## 6. Known Gaps / TODO

**`contact_email` is currently a test address.** `calendar-config.json` for Ivy-T has `contact_email: "john.mcgeagh@gmail.com"`. This must be changed to the client's actual address before the pipeline goes live. Update via `pnpm patch-calendar-config <slug> <channel>` (edit the `PATCH` block in `src/patch-calendar-config.ts` first).

**No monthly scheduler exists.** The `content-cycles` BullMQ consumer handles `extract-voice` and `apply-voice` jobs only. There is no cron or recurring trigger that enqueues the `request-email` step. The pipeline is manually triggered via `send-request-email` until a scheduler is built.

**No server-side sales-CSV producer.** The Shopify export is done manually by the client or operator and uploaded to Drive via `pnpm drive-upload`. The pipeline degrades gracefully to engagement-only if the file is absent, but the lean-line is weaker without sales data.

**Lean-line theme-invention is prompt-controlled, not guaranteed.** The system prompt prohibits asserting themes or audience preferences from engagement data ("clearly resonating", "the data is telling us"), but model compliance is imperfect. The lean-line should always be reviewed before the draft is sent. The client is the final backstop.

**`drive.file` OAuth scope — web-UI uploads are invisible.** The Drive client operates under the `drive.file` scope, which restricts visibility to files the app itself created. Any file dropped into the Drive folder via the Google Drive web interface is owned by the user, not the app, and will not appear in `listFiles` or be readable by the worker. All data files must be uploaded via `pnpm drive-upload` or an app-created producer (e.g. `ig-trawl`).
